# Концептуальная модель данных

## Принято: границы модели

Основные сущности — Source, Snapshot, Page и Block. Перечень атрибутов концептуальный: физическая схема, миграции, SQL-типы, индексы, форматы JSON и окончательные Go-типы проектируются при реализации хранения.

Учётные записи и служебные данные аутентификации описаны в [auth.md](auth.md); они не превращают предметную модель CMS в универсальную платформу.

## Source

Внешний источник: идентификатор, тип, внешний URL или идентификатор, название, параметры получения, периодичность и признак активности.

На первом этапе Source указывает на конкретную заранее выбранную публикацию Telegram. Полное сканирование каналов не требуется. Тип источника допускает последующее добавление веб-страниц, API, RSS, документов или ручных загрузок без создания таких fetchers заранее.

Состояние синхронизации должно позволять показать последнюю попытку, последнее успешное получение и текущую ошибку. Конкретное размещение этих служебных данных определяется при проектировании хранения. Отключение фонового обновления не равнозначно отзыву разрешения на публикацию.

## Snapshot

Исходное содержимое Source с метаданными, контрольной суммой, временем получения и временем изменения во внешней системе, если оно известно. Snapshot сохраняется до нормализации и обработки.

Для Telegram существенны текст, форматирование, ссылки и другие поддерживаемые атрибуты. Контрольная сумма не должна учитывать только текст и игнорировать изменения ссылок или форматирования. Конкретный состав сравниваемых данных определяется для fetcher; время очередного опроса не должно само создавать новую версию.

Snapshot соответствует версии содержимого, а не каждой попытке опроса. При неизменившемся содержимом обновляется состояние успешной проверки, без дублирования снимка. Старые снимки обеспечивают возможность повторной обработки и восстановления, но сами по себе не являются публичной историей.

## Page

Страница сайта: идентификатор, постоянный URL или slug, заголовок, описание, метаданные, основной язык и статус публикации. Состоит из упорядоченных блоков; может существовать без внешних источников. Язык можно хранить в метаданных; отдельная модель переводов не требуется. Способ задания языка и значение по умолчанию определяются перед реализацией управления страницами.

Новая страница по умолчанию является черновиком. Первую публикацию явно выполняет редактор; снятие с публикации сохраняет содержимое и историю. Полное поведение описано в [редакционном жизненном цикле](content-pipeline.md#принято-редакционный-жизненный-цикл). Технические имена статусов определяются при реализации.

Географическая или предметная иерархия не навязывается. URL опубликованных страниц стабильны: изменение содержимого или навигации не меняет адрес. Если смена URL необходима, предпочтительно сохранять перенаправление со старого адреса. Детали адресации и перенаправлений определяются перед реализацией управления страницами; отдельные навигационные сущности заранее не вводятся.

## Block

Блок принадлежит странице, имеет позицию, тип и параметры. Содержит ручной текст либо использует Source и правила обработки. Возможны другие типы по мере появления подтверждённых потребностей.

Для импортируемого блока хранятся последний успешно подготовленный результат и связь с исходным Snapshot. Должно быть понятно, по какой редакции правил получен результат. Результат предпросмотра не заменяет действующее публичное содержимое; правила его применения описаны в [конвейере](content-pipeline.md#принято-редакционный-жизненный-цикл). Ошибка новой обработки не заменяет успешный результат пустым или частичным содержимым. Физический способ хранения результатов определяется при реализации.

Один Source используется несколькими блоками на одной или разных страницах с независимыми правилами. Изменение правил одного блока не меняет оригинал и результаты других блоков. Нужда в переиспользуемых между страницами экземплярах самих блоков пока не установлена.

## Связи и история

- Source имеет множество Snapshot и может использоваться множеством Block.
- Page содержит упорядоченное множество Block.
- Импортируемый результат Block связан со Snapshot своего Source; ручному блоку эта связь не нужна.

Предусматриваются история изменений и восстановление предыдущих редакций страниц, блоков и правил. Хранение одних Snapshot недостаточно для восстановления ручного текста и композиции страницы. Формат редакций, сроки хранения и минимальный интерфейс восстановления определяются при реализации; универсальная система версионирования не требуется.

Восстановление — согласованное редакторское изменение с журналированием. Оно не обходит действующее снятие публикации или отзыв разрешения на контент. Снятие страницы с публикации само по себе не является удалением её данных. Политика хранения удалённых материалов принимается отдельно от обычного восстановления.

## Временные отметки

Различаются последняя попытка получения, последнее успешное получение, время изменения оригинала и публикация подготовленного результата. Время изменения оригинала может отсутствовать. Проверка неизменившегося источника не является новой публикацией, а повторная обработка старого снимка может ею быть. Правила публичного отображения описаны в [конвейере](content-pipeline.md).
