# Эксплуатация

## Принято: production

Приложение работает одним непривилегированным процессом в одном Docker-контейнере на VPS.
TLS и маршрутизацию обеспечивает существующий общий Traefik. Приложение не управляет ACME,
DNS и сертификатами. Локально Docker не собирается, не запускается и не тестируется.
Приведённые команды предназначены для будущего выполнения на production/build-хосте.

Dockerfile собирает Go 1.27 без CGO и переносит бинарник и LICENSE в
gcr.io/distroless/static:nonroot. Используется пользователь nonroot базового образа
(UID/GID 65532:65532), без shell и toolchain. CA-сертификаты предоставляет базовый образ.
Используется UTC. ENTRYPOINT передаёт сигналы приложению непосредственно.

Сборочная система назначает VERSION через build argument. Без него используется dev. Публикация
образа требует выполнения [релизных условий](releases.md), включая
проверку соответствующих исходников и лицензионных уведомлений зависимостей.

```sh
docker build --build-arg VERSION=dev -t wcs-guide:dev .
```

## Подготовка постоянного хранилища

Монтируется весь каталог /data на локальной файловой системе, включая журналы SQLite. Внешний
volume создаётся отдельно от Compose и сохраняется при пересоздании приложения. Dockerfile
объявляет VOLUME ["/data"] и ENV DB_PATH=/data/wcs-guide.db. Подготовка каталога, тома и прав
доступа — ответственность оператора окружения, а не Dockerfile или Makefile. Каталог должен
разрешать пользователю nonroot (65532:65532) создание БД и файлов журнала. Существующие данные
автоматически не изменяются. Для bind mount права задаются на хосте. Не использовать chmod 777,
сетевую файловую систему или автоматический сброс схемы. Совместимость экспериментальных схем
ограничена [правилами хранения](development.md#реализованное-sqlite-хранилище).

Перед запуском HTTP приложение проверяет чтение и запись БД, включая создание журнала
SQLite. Проверка записи повторно сохраняет текущую версию схемы в короткой транзакции,
не меняя схему и пользовательские данные. При ошибке доступа приложение завершается
с кодом 1; каталоги и права автоматически не исправляются. Проверка относится к моменту
запуска и не гарантирует доступность диска в дальнейшем.

## Конфигурация Compose и Traefik

Production-конфигурация использует один сервис, внешний том и внешнюю сеть Traefik.
Порты контейнера на хост не публикуются. Оператор передаёт BASE_URL; DB_PATH уже задан
в образе и отдельно не требуется. Локально DB_PATH задаётся в .env.dev. Операционные
переменные подстановки Compose не являются параметрами приложения:

| Переменная Compose | Назначение |
|---|---|
| WCS_IMAGE | Подготовленный образ |
| WCS_DATA_VOLUME | Имя заранее созданного внешнего тома |
| TRAEFIK_NETWORK | Имя существующей внешней сети |
| TRAEFIK_ENTRYPOINT | Имя HTTPS entrypoint общего Traefik |

Перед запуском назначить эти переменные в окружении оператора. При необходимости настроить
label certificate resolver с реальным существующим именем. Маршрут задан для wcs.guide и
соответствует BASE_URL=https://wcs.guide. При смене домена согласованно изменить оба значения.
Backend — HTTP :8080. Отдельный Traefik, доступ к Docker socket и управление сертификатами
приложению не требуются.

Оператор подготавливает собственный compose.prod.yaml с этими настройками. Пример команд:

```sh
docker compose -f compose.prod.yaml up -d
docker compose -f compose.prod.yaml logs -f
curl --fail https://wcs.guide/healthz
docker compose -f compose.prod.yaml stop
```

Health возвращает ok и подтверждает работоспособность HTTP после начального открытия БД, а не
постоянную проверку диска. SIGTERM запускает завершение с timeout 10 секунд; в Compose следует
задать stop_grace_period: 15s, оставив запас до принудительной остановки. Логи — текст
INFO/WARN/ERROR в stderr.

## Обновление и восстановление

Перед обновлением сохранить согласованную резервную копию по правилам development.md.
Назначить новый WCS_IMAGE и пересоздать сервис с тем же внешним томом. Данные не включаются
в образ и не удаляются при обычном пересоздании. Миграции применяются при запуске; downgrade
не реализован. Не удалять том при обновлении и не копировать открытый SQLite-файл как
гарантированно корректную резервную копию. Проверять восстановление на отдельной копии.

Docker-сборка, контейнерный запуск, права тома, Traefik, persistence и сигналы в контейнере
локально не проверялись и не должны проверяться. Файлы проходят только просмотр содержимого.
