# Аутентификация и редакторский доступ

## Назначение

В ближайшей перспективе редактором работает владелец проекта на основном ноутбуке.
Модель поддерживает несколько пользователей и ключей. Публичный сайт входа не требует.
Паролей, OAuth, email, SMS, JWT-сессий и внешнего сервиса идентификации нет.

Роли: admin управляет всем содержимым и пользователями; editor — всем содержимым.
Блокировка и текущая роль проверяются по БД. Защиты последнего администратора нет:
доверенный оператор сервера восстанавливает доступ через CLI.

## Адреса и конфигурация

EDITOR_BASE_URL обязателен. Production: https://editor.wcs.guide; публичный BASE_URL —
https://wcs.guide. Один процесс выбирает обработчик по настроенному Host, неизвестный хост
получает 421. X-Forwarded-* не определяют параметры аутентификации.

Локально BASE_URL=http://127.0.0.1:8080, EDITOR_BASE_URL=http://localhost:8080.
Оба адреса ведут на один ноутбук и порт, но браузер разделяет их cookies.
HTTP редактора допускается исключительно для localhost. TLS выполняет Traefik.
Production-маршрутизация направляет оба домена в один контейнер; VPS приложение не настраивает.
RP ID — hostname редактора, Origin — полный настроенный адрес. Изменение RP ID после
регистрации может потребовать новых ключей доступа.

## Первый администратор

Загрузите доверенный .env.dev средствами shell, затем выполните:

```sh
set -a
. ./.env.dev
set +a
CGO_ENABLED=0 go run ./cmd/wcs-guide admin bootstrap owner 'Владелец'
```

Команда создаёт пользователя, выводит адрес /register и код на 30 минут.
При существующих пользователях bootstrap завершается ошибкой, ничего не меняя.
Откройте редакторский адрес, введите код и зарегистрируйте Passkey. После регистрации
перейдите на /login, введите логин и подтвердите владение ключом.

Код — случайные 32 байта Base64URL. В SQLite хранится SHA-256. Код передаётся через форму,
не через URL. Разрешение погашается одной транзакцией с регистрацией ключа.
CLI не запускает Telegram, планировщик или HTTP. Сервер может продолжать работать:
CLI использует короткие транзакции того же файлового хранилища.

В distroless-контейнере shell не требуется:

```sh
docker exec -it CONTAINER /wcs-guide admin bootstrap owner 'Владелец'
docker exec -it CONTAINER /wcs-guide admin recover owner
```

Эти команды предназначены для оператора production; локально Docker не запускается.

## Восстановление

```sh
CGO_ENABLED=0 go run ./cmd/wcs-guide admin recover owner
```

Одна транзакция активирует существующего пользователя, назначает admin, удаляет его
credentials, сессии и разрешения и создаёт новое разрешение регистрации на 30 минут.
WebAuthn User ID сохраняется. Неизвестный логин не создаёт пользователя.
Старые незавершённые операции отклоняются при завершении: разрешение или credential
уже отозваны. Другие пользователи и материалы не изменяются.

## WebAuthn и сессии

Используется go-webauthn/webauthn v0.18.2 (BSD-3-Clause). Криптографические проверки
выполняет библиотека. Требуется user verification; attestation preference — none.
Вход начинается с логина. Привязки к Touch ID и конкретному браузеру нет.

Пользователь имеет непрозрачный случайный WebAuthn ID длиной 32 байта. Credentials хранят
полное JSON-представление библиотеки, включая публичный ключ, flags, счётчики, transports
и данные attestation. Приватные ключи не покидают аутентификатор.
При обновлении библиотеки необходимо проверять совместимость сохранённых credentials.

Операции регистрации и входа хранятся в памяти: максимум 128, срок 5 минут.
Случайная HttpOnly-cookie связывает операцию с браузером. Finish атомарно удаляет операцию
до проверки ответа. Перезапуск требует начать незавершённый вход заново.
Общий предел начала и завершения аутентификации — 60 запросов в минуту.

После входа сервер создаёт случайный токен сессии на 30 дней, в SQLite сохраняет SHA-256.
Сессии переживают перезапуск. Роль читается из users при каждом защищённом запросе.
Блокировка пользователя отзывает сессии. Logout удаляет текущую сессию.

Production-cookie __Host-wcs-editor-session имеет Secure, HttpOnly, SameSite=Strict,
Path=/ и не имеет Domain. На HTTP localhost используется wcs-editor-session без Secure.
Настройки определяются конфигурацией, а не входящими forwarded-заголовками.

## Маршруты и защита

Редактор предоставляет GET /login, /register, / и собственные /static/editor.js,
/static/editor.css. Главная страница требует сессию и показывает имя, роль и выход.
POST /auth/login/begin и /finish выполняют вход; /auth/register/begin и /finish — регистрацию.
POST /logout завершает сессию. GET не регистрирует ключи и не отзывает доступ.

Изменяющие запросы проходят http.CrossOriginProtection и точную проверку обязательного Origin.
JSON-запросы ограничены 64 КиБ. CSP разрешает собственные стили, скрипты и fetch;
inline-код, фреймы и внешние ресурсы запрещены. Ответы имеют no-store и no-referrer.
Редакторский robots.txt запрещает индексацию, X-Robots-Tag содержит noindex, nofollow.
Публичный sitemap не содержит адресов редактора.

Регистрационные коды, сессии, cookies и ответы аутентификатора не журналируются.
Служебные ошибки не раскрывают посетителям детали БД и WebAuthn.

## Проверки и ограничения

Автоматические проверки используют временную SQLite и вектор NoneES256 из тестов библиотеки.
Проверяются Origin, challenge, UV, одноразовость, восстановление, сессии и роли.
Уведомление авторов вектора сохранено вместе с fixtures.

Ручная проверка на MacBook: bootstrap, регистрация, вход, перезапуск с сохранением сессии,
выход, повторный вход, recover, регистрация нового ключа и отказ старым сессиям и ключам.
Реальная регистрация требует участия владельца и автоматически не выполняется.

Управление пользователями, приглашениями, устройствами и содержимым через браузер отложено.
Аудита и истории входов нет. Межплатформенные и мобильные сценарии не проверяются в этом этапе.
